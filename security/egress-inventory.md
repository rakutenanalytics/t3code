# T3-owned egress baseline

Compiled builds embed [managed-policy.json](managed-policy.json) through the [build loader](../scripts/lib/managed-policy.ts). Gates use one [policy helper](../packages/shared/src/managedPolicy.ts); the runtime adapter denies all modeled capabilities when the file is absent or the baked value is null (raw nullable helpers retain upstream semantics). The [contract](../packages/contracts/src/managedPolicy.ts) defines the allow list. [allowlist.json](allowlist.json) is a review inventory, not a firewall. Unlisted dynamic destinations require separate approval.

Safe fork release installation uses the root [install.sh](../install.sh) and [t3safe](../scripts/safe/t3safe), with public fork release/checksum downloads. Managed upstream CLI/service/SSH download paths and the fork-built npm launcher deny `upstreamUpdate` by default; they are not redirected to safe artifacts. External npm packages and the legacy standalone scripts/install.sh and scripts/install.ps1 can still install unmanaged applications outside this distribution. Mobile Expo OTA remains excluded from distribution.

Adding an attachment can upload its bytes before the message is sent. The web/mobile composer sends its name, MIME type and size to the selected environment's authenticated `attachments.createUploadUrl` RPC, which requires `orchestration:operate`; bytes go to that environment using the signed, expiring upload URL. Copying an attachment between environments can first download it from the source environment. These are explicit attachment actions, with no third-party upload destination. See [mobile upload ownership](../apps/mobile/src/state/composer-attachment-uploads.ts), [composer imports](../apps/web/src/components/chat/useComposerContextImport.ts) and [server upload tokens](../apps/server/src/assets/AttachmentUpload.ts).

Diagram rendering runs automatically for Markdown, including PR descriptions. The [Pele integration](../apps/web/src/components/chat/MermaidDiagram.tsx) disables links and images, strips resource attributes and style elements, and filters external CSS URLs from all attribute values in both SVG and MathML paths. Escaped CSS and image functions carrying resource strings are discarded. Diagram content grants no outbound permission.

The mobile native composer icon loaders can fetch HTTP(S) image bytes, but their [URI source](../apps/mobile/src/lib/contextChipIconSource.ts) resolves a fixed generated map of bundled icons. Production uses local assets; development may use the Metro asset server. Workspace/user/agent input selects a known icon name, never an icon URL. This review grants no arbitrary remote icon destination.

The [Windows signing helper](../scripts/lib/windows-jsign.ts) runs only for explicit Windows builds with Azure signing configuration. A maintainer-provided `T3CODE_JSIGN` or `jsign` on the build host's PATH receives signing credentials through its environment, contacts the configured Azure signing service and submits an executable digest to `http://timestamp.acs.microsoft.com` for RFC 3161 timestamping. This preserves the existing Windows signing endpoint; the safe macOS-only workflow does not invoke it.

The [Electron runtime repair script](../apps/desktop/scripts/ensure-electron-runtime.mjs) first uses Electron's installer/cache. On a cache miss, the locked `@electron/get` downloader defaults to GitHub Electron releases; inherited `ELECTRON_MIRROR`, custom path/version, npm mirror and proxy settings can select a build-host destination. Bundled checksums are the default, but explicit `electron_use_remote_checksums` settings select remotely fetched checksums. These are trusted build-host configuration, not application or agent-controlled settings. The installer and downloader were inspected in the Electron package review. The direct GitHub ZIP fallback independently verifies SHA-256 against the locked Electron package's bundled `checksums.json` before extraction. A missing checksum or mismatch stops that fallback.

Explicit [thread CLI commands](../apps/server/src/cli/thread.ts), also reachable by agents through shell, use the persisted local server origin's `/mcp` endpoint. They require a live recorded server process before issuing a temporary full-access client session, revoke that session when the command ends, and send only the requested project/thread operations and messages. This is an owner-level CLI backed by local auth storage; it does not inherit an invoking provider thread's permission ceiling. Provider shell sandboxing remains outside the managed build's threat model. The local runtime-state file remains trusted configuration, as for the existing project CLI; this process check does not cryptographically authenticate a listener or protect against a local attacker who can replace application state.

Merging a reviewed PR approves automatic public tag/release publication on GitHub. The upstream watcher writes public sync issues from a validated tag and a fixed template on GitHub; it does not change source code or approve releases.

CI adds literal host/URL checks and reviewed whole-file source fingerprints and literal-host inventories, plus a lockfile/manifest/build-permission baseline. File-specific literal annotations include gated hosts, documentation/schema links, optional tooling and synthetic examples. Hashes identify illustrative addresses without duplicating private-looking sample names. New statements still require diff review, even for an approved host.

The dependency audit adds unauthenticated metadata reads from `registry.npmjs.org` only with `dependency-scan.ts --online`, including the PR advisory job. It rejects redirects and times out each request. Package changes require separate tarball reviews and fingerprint-bound approvals; see [maintenance](../docs/safe-fork/MAINTAINING.md). Offline scanning makes no registry requests. This grants no runtime network capability.

This inventory covers runtime paths, not every transitive install/build endpoint. Build toolchain downloads and dependency lifecycle destinations still need review. Redirects and SDK-owned endpoints must be reviewed before treating the host inventory as enforceable network policy.
