# T3-owned egress baseline

Compiled builds embed [managed-policy.json](managed-policy.json) through the [build loader](../scripts/lib/managed-policy.ts). Gates use one [policy helper](../packages/shared/src/managedPolicy.ts); the runtime adapter denies all modeled capabilities when the file is absent or the baked value is null (raw nullable helpers retain upstream semantics). The [contract](../packages/contracts/src/managedPolicy.ts) defines the allow list. [allowlist.json](allowlist.json) is a review inventory, not a firewall. Unlisted dynamic destinations require separate approval.

Safe fork release installation uses the root [install.sh](../install.sh) and [t3safe](../scripts/safe/t3safe), with public fork release/checksum downloads. Managed upstream CLI/service/SSH download paths and the fork-built npm launcher deny `upstreamUpdate` by default; they are not redirected to safe artifacts. External npm packages and the legacy standalone scripts/install.sh and scripts/install.ps1 can still install unmanaged applications outside this distribution. Mobile Expo OTA remains excluded from distribution.

Merging a reviewed PR approves automatic public tag/release publication on GitHub. The upstream watcher writes public sync issues from a validated tag and a fixed template on GitHub; it does not change source code or approve releases.

CI adds literal host/URL checks and reviewed whole-file source fingerprints and literal-host inventories, plus a lockfile/manifest/build-permission baseline. File-specific literal annotations include gated hosts, documentation/schema links, optional tooling and synthetic examples. Hashes identify illustrative addresses without duplicating private-looking sample names. New statements still require diff review, even for an approved host.

The dependency audit adds unauthenticated metadata reads from `registry.npmjs.org` only with `dependency-scan.ts --online`, including the PR advisory job. It rejects redirects and times out each request. Package changes require separate tarball reviews and fingerprint-bound approvals; see [maintenance](../docs/safe-fork/MAINTAINING.md). Offline scanning makes no registry requests. This grants no runtime network capability.

This inventory covers runtime paths, not every transitive install/build endpoint. Build toolchain downloads and dependency lifecycle destinations still need review. Redirects and SDK-owned endpoints must be reviewed before treating the host inventory as enforceable network policy.
